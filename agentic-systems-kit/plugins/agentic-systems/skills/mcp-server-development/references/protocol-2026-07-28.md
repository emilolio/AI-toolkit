# MCP protocol notes: revision 2026-07-28

Protocol-level detail behind `mcp-server-development`. Read October 2026 from the specification. **MUST/SHOULD** mark spec requirements. Check https://modelcontextprotocol.io/specification for a newer revision first.

## What changed from 2025-11-25

| Area | 2025-11-25 and earlier | 2026-07-28 |
|---|---|---|
| Handshake | `initialize` / `notifications/initialized` | removed; every request carries `io.modelcontextprotocol/protocolVersion` and `io.modelcontextprotocol/clientCapabilities` in `_meta`; servers **MUST** implement `server/discover` (versions, capabilities, `instructions`, identity) |
| Sessions | `Mcp-Session-Id` | removed; list results **MUST NOT** vary per connection (they **MAY** vary by the request's authorisation); state via explicit handles |
| Server → client requests | sampling, elicitation, roots sent as requests | **Multi Round-Trip Requests (MRTR)**: the server returns `resultType: "input_required"` with `inputRequests`; the client retries with `inputResponses` and a new JSON-RPC id |
| Change notifications | HTTP GET stream, `resources/subscribe` | one `subscriptions/listen` long-lived stream |
| Results | | every result carries `resultType`; list/read results carry required `ttlMs` and `cacheScope` (`public` / `private`) |
| HTTP headers | | `MCP-Protocol-Version`, `Mcp-Method`, and `Mcp-Name` (for `tools/call`, `resources/read`, `prompts/get`) required; mismatch → 400 `HeaderMismatch` (-32020) |
| Tasks | core | moved to the `io.modelcontextprotocol/tasks` extension |
| Errors | resource not found -32002 | -32602; -32020..-32099 reserved for the spec; unsupported version → -32022 with a `supported` list |
| Schemas | | full JSON Schema 2020-12 in `inputSchema`/`outputSchema`; `structuredContent` may be any JSON value |
| Removed | | `ping`, `logging/setLevel`, roots list-changed notification, SSE resumability (`Last-Event-ID`) |

**Deprecated** (minimum 12-month window): roots (use tool parameters / URIs / config), sampling (call your LLM provider directly), logging (stderr or OpenTelemetry; per-request level via `_meta`), HTTP+SSE transport, `includeContext` values `thisServer`/`allServers`, dynamic client registration (use Client ID Metadata Documents).

**Dual-era servers.** A server may serve both eras: an `initialize` request selects legacy semantics. A 2026-07-28-only server SHOULD answer GET/DELETE with 405 and ignore `Mcp-Session-Id`. Dual-era clients probe with `server/discover`.

## MRTR (input required)

- Allowed on `tools/call`, `resources/read`, `prompts/get` only.
- `inputRequests` may contain elicitation, sampling or roots requests, only for capabilities the client declared.
- Every input-required result **MUST** include `inputRequests` or `requestState`.
- `requestState` is attacker-controlled from the server's point of view; integrity-protect it (HMAC/AEAD) when it affects authorisation or business logic; bind principal, TTL and request digest. Clients echo it unmodified.
- Servers **MUST NOT** assume the client will retry.

## Elicitation

- **Form mode**: flat schemas of primitives only (string with email/uri/date/date-time formats, number, boolean, single/multi-select enums).
- **URL mode**: send the user to a URL out-of-band, e.g. for third-party OAuth. **MUST** be used instead of form mode for passwords, API keys, tokens and payment credentials.
- No PII or credentials in the URL; no pre-authenticated URLs; verify that the user completing the flow is the one who triggered it.
- Handle `accept`, `decline` and `cancel`.

## Tools: required details

- `inputSchema` **MUST** be a valid JSON Schema object (not null).
- If `outputSchema` is present, servers **MUST** return conforming `structuredContent`; clients SHOULD validate. Also return the serialised JSON in a text block (SHOULD) for older clients.
- Servers **MUST** validate inputs, enforce access control, rate-limit and sanitise outputs.
- Clients SHOULD keep a human able to deny invocations, show inputs before calling, validate results, apply timeouts and audit-log.

Annotation defaults: `readOnlyHint` false, `destructiveHint` **true**, `idempotentHint` false, `openWorldHint` **true**. `destructiveHint` and `idempotentHint` are meaningful only when not read-only. Clients **MUST** treat annotations from untrusted servers as untrusted.

## Resources, prompts, utilities

- Resources: `resources/list`, `resources/read`, `resources/templates/list` (RFC 6570). Missing resource → -32602, never an empty `contents`. Validate URIs, sanitise `file://` paths. Annotations: `audience`, `priority` (0–1), `lastModified`.
- Prompts: `prompts/list`, `prompts/get` with arguments; validate inputs and outputs.
- Pagination: opaque cursors; clients **MUST NOT** parse them; an empty-string cursor is valid.
- Progress: client sends `_meta.progressToken`; progress strictly increases; stop after completion.
- Cancellation: on Streamable HTTP, closing the response stream is cancellation; on stdio send `notifications/cancelled`. Always enforce a maximum timeout.
- Completions: `completion/complete`, ≤100 values; validate and rate-limit.
- Tracing: OpenTelemetry `traceparent` conventions in `_meta`.

## Extensions

Negotiated via `capabilities.extensions`; identifiers `{vendor-prefix}/{name}`; if the other side lacks an extension, fall back to core behaviour or reject.

- **Tasks** (`io.modelcontextprotocol/tasks`): result `resultType: "task"` with `taskId`, `ttlMs`, `pollIntervalMs`; `tasks/get`, `tasks/update` (mid-flight input), `tasks/cancel`; statuses `working`, `input_required`, `completed`, `failed`, `cancelled`. Never return a task to a client that did not declare the extension.
- **MCP Apps** (`io.modelcontextprotocol/ui`): tool `_meta.ui.resourceUri` → `ui://` resource with MIME `text/html;profile=mcp-app`, rendered in a sandboxed iframe that talks to the host over postMessage JSON-RPC; `_meta.ui.csp` and permissions declare external origins and device access. Supported by Claude apps, ChatGPT, VS Code and others. Always return text for non-UI hosts.
- **Auth extensions**: OAuth client credentials (machine-to-machine), enterprise-managed authorisation.
- Skills over MCP: draft at time of writing.

## Authorisation flow (HTTP)

1. Client calls the server without a token → **401** with `WWW-Authenticate: Bearer resource_metadata="https://mcp.example.com/.well-known/oauth-protected-resource", scope="…"`.
2. Client fetches Protected Resource Metadata (RFC 9728; servers **MUST** implement) → `authorization_servers`.
3. Client fetches authorisation server metadata (RFC 8414 or OIDC discovery; both **MUST** be supported by clients).
4. Client registration, in order: pre-registered → Client ID Metadata Document (HTTPS URL as `client_id`) → dynamic registration (deprecated) → ask the user. Credentials keyed by issuer.
5. Authorisation code flow with PKCE; the `resource` parameter (RFC 8707, the server's canonical URI) **MUST** be in both authorisation and token requests; validate `iss` (RFC 9207) before redeeming the code.
6. Every request carries `Authorization: Bearer …` (never in the query string). Server validates the audience; invalid → 401; insufficient scope → 403 `insufficient_scope` with the full scope set needed; clients step up with the union of scopes.

Servers **MUST NOT** accept or transit tokens not issued for them. Token passthrough bypasses rate limiting and validation, breaks audit trails, and turns stolen tokens into an exfiltration proxy.

## Security best-practice summary (spec page)

- **Confused deputy** (proxy with static third-party client ID): per-client consent registry before forwarding; consent page shows client, scopes, redirect URI; CSRF and anti-framing; `__Host-` signed cookies bound to the client; exact redirect match; single-use `state` (~10 min) set after consent.
- **SSRF** during discovery (client side): HTTPS only except loopback in development; block private/loopback/link-local ranges; validate every redirect hop; egress proxy; pin DNS between check and use.
- **State handle hijacking**: handles are not authentication; random, expiring, bound to the verified user.
- **Local server compromise**: show the full install command and require approval; highlight dangerous patterns; sandbox; stdio or token-protected local HTTP.
- **OAuth URL handling** (clients): only `https` (or loopback `http`); never open URLs via a shell; CSP.
- **Scope minimisation**: minimal baseline scope, incremental elevation, no wildcard scopes, log elevations.
